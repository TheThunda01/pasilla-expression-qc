# Assumptions and interpretation boundaries

An assumption makes a calculation possible; it is not automatically a finding. The [methods](methods.md) specify the calculations, and [references](references.md) separate published evidence from implementation choices.

| Assumption or choice | Rationale and supporting evidence | What is checked | Consequence if it fails |
| --- | --- | --- | --- |
| The pinned count table and annotation are the intended inputs. | Fixing a source revision makes this teaching example repeatable. The upstream package documents their derivation; it does not independently verify the original experiment. | SHA-256 hashes, byte counts, integer/nonnegative counts, unique identifiers, and complete annotation matches. | Correctly computed results could still describe the wrong or biologically mislabeled samples. |
| Removing the terminal `fb` maps package annotation names to count columns. | This is a dataset-specific naming convention, visible in the pinned files; it is not a general RNA-seq rule. | Unique, exact one-to-one identifier matches after suffix removal. | A future dataset could require a different mapping; the current program should reject unmatched inputs. |
| Package labels define the displayed groups. | Retaining source labels avoids inventing a reconciliation. The vignette gives three treated/four untreated libraries, while the original article's reported allocation is reversed. | Structural agreement with the pinned annotation is checked. **Biological reconciliation remains untested and unresolved.** | Treatment interpretations could be wrong. No relabeling or treatment-effect inference is justified by this workflow. |
| Libraries are the observational units in plots. | One library is one row of sample coordinates. Paired mates and sequencing lanes do not create independent biological replication. | The seven named columns and read-type allocation are enumerated. Independence and all experimental histories are not established here. | Treating technical measurements as biological replicates would overstate evidence; no inferential test is run. |
| Total-count scaling provides a useful relative-depth comparison. | It removes the column-total scale but is sensitive to composition changes; [Robinson and Oshlack (2010)](references.md#robinson-2010) explain the problem. | Factors and largest-gene fractions are reported. The biological validity of total-count scaling is **not established**. | Relative differences can reflect composition rather than the intended abundance comparison. |
| A stable central gene reference makes median-ratio scaling useful. | [Anders and Huber (2010)](references.md#anders-2010) motivate robust relative normalization. Widespread directional changes can undermine the reference. | Only genes positive in all relevant samples contribute; the log-median convention and geometric centering have numerical tests. No absolute-RNA reference checks the biological assumption. | Factors may absorb real global change or introduce misleading relative differences. Agreement with total-count scaling does not resolve this. |
| A fixed gene filter and $`+1`$ offset are useful exploratory choices. | At least 10 counts in at least three samples limits sparse features in the display. The offset allows logarithms at zero. These are pragmatic settings, not literature-derived acceptance thresholds. | The retained 8,148 genes are fixed across PCA comparisons; the scale and offset are recorded. Alternative settings were not systematically assessed. | Low-count geometry or apparent separation can change. The plots do not establish a unique biological structure. |
| Centered, unstandardized PCA and two dimensions answer the display question. | Keeping gene variance weights explicit gives an inspectable summary. Two dimensions are readable but discard remaining directions. | The code centers genes, uses SVD, records variance fractions, and fixes an arbitrary sign convention. | A pattern outside the displayed dimensions can be missed; component signs carry no biological meaning. |
| The additive annotation matrix is a useful identifiability check. | Separate condition and read-type indicators expose exact linear dependence; [DESeq2's design guidance](references.md#deseq2-docs) explains confounding. | Rank three, residual dimension four, and all four cells are reported; one cell has one sample. No additive model or interaction model is fitted. | Full rank can coexist with poor precision, interactions, or unmeasured confounding. It does not validate a treatment analysis. |
| Omitting one sample while fixing genes and reference depth isolates a defined influence question. | This deliberately separates sample inclusion from repeated feature selection and arbitrary count-scale changes. | Every omission is evaluated and normalization is refitted as documented. | It cannot estimate predictive performance or decide whether a sample should be excluded. |
| Procrustes shape difference is a useful display comparison. | Orthogonal alignment removes arbitrary orientation; additional centering/scaling removes translation and size. | Synthetic tests cover these invariances and known shape changes. No biological cutoff is calibrated. | Overall scale changes are hidden and a residual cannot be read as biological error or experimental uncertainty. |
| The selected result bundle is the intended reference. | Byte snapshots support transfer; numerical comparison allows declared rounding differences. | Inventoried artifacts, labels, finite values, and selected schemas are checked. Tolerances are engineering settings. | Mixed but label-consistent artifacts or two equally wrong calculations can agree. Files outside the inventory and all matrix relationships are not independently verified. |
| Files remain stable during sequential reads and the runtime supports the specified dependencies. | These are operational conditions for reproducible execution. | Environment versions are recorded; known failure paths are tested. No filesystem-wide lock or cross-platform certification is supplied. | Concurrent edits, environment changes, or final write failures can invalidate a transfer or leave incomplete output. Use separate output directories and check exit status. |

No row in this table supplies a clinical validation claim, a causal conclusion, or permission to discard an influential sample. The [practical-use guide](practical-use.md) explains how to inspect a rerun within these boundaries.
